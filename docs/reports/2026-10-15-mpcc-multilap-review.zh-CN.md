# 2026-10-15 MPCC：连续圈运行稳定，仍有重复的弯外跟踪偏差

[English](2026-10-15-mpcc-multilap-review.md)

实车记录 `022604_194643_race` 连续 enabled RUNNING **178.505 s**，完成 **15 个完整圈，随后第 16 圈未完成**。原生 EKF 纵向速度均值 **3.058 m/s**、峰值 **4.671 m/s**。4.5 m/s 目标阶段完整圈约 **11.09 s**，横向误差 RMS 仍约 **9.9 cm**，并在相同参考位置重复出现。3,564 次请求中没有记录求解失败或 deadline miss。这些数据支持本次运行的执行与时序结论，不能证明外部真值下的跟踪精度，也不能替代新旧控制器的受控对照。

本报告只覆盖最新连续圈实验；此前单圈实验及其不同统计口径保留在 [2026-10-10 外场复盘](2026-10-10-mpcc-field-review.md)。

## 证据与统计口径

源复盘目录名为 `022604-mpcc-review`，对应 `022604_194643_race`，日期采用 Asia/Shanghai 的 2026-10-15。仓库携带[逐圈 CSV](assets/2026-10-15-mpcc-multilap/laps.csv)、[精选指标 JSON](assets/2026-10-15-mpcc-multilap/summary.json) 和[附件来源清单](assets/2026-10-15-mpcc-multilap/artifact-manifest.json)。清单记录来源 basename、相对名称和 SHA-256；完整 bag 与原始提取文件保留在外部。`selected_cdr_sha256` 是选定提取消息序列化内容的哈希，**不是整个 SQLite bag 的哈希**。

数值分析使用各消息 header 源时间：先用整数纳秒减去 bag 起始接收时间，再转秒。RUNNING 位于 bag 相对 **41.926417–220.431559 s**。跟踪统计取约 10 Hz 的 **1,786 个 enabled RUNNING 诊断样本**；速度取相同窗口的 **35,526 个原生 EKF 样本**与 **17,850 个原生轮速样本**，包含起步。原提取报告选定话题解码错误为零，所检查核心流没有源时间非递增或非有限值。原 `validation.json` 记录核验通过；本次整理另行复算了圈分组、原始提取速度/诊断统计与 runtime 时序，没有完整回放原始 bag。

Runtime 时长来自日志自身的 steady clock。逐帧查看器使用 bag 接收时间及当时最新已收到的 map→odom TF，因此事件标签与源时间分析可有亚毫秒差异；不能混用这些时钟估计物理响应。

## 跟踪参考点与不确定性

全段 RUNNING 诊断横向误差 RMS **9.866 cm**、均值 **−8.378 cm**、绝对最大值 **23.084 cm**。**1,682/1,786（94.18%）** 样本为负误差。在 |参考曲率|>0.15 m⁻¹ 的样本中，**962/1,109（86.74%）** 满足误差×曲率<0，即本报告采用的几何弯外偏差定义。这是相对冻结参考与估计定位的重复偏差，不能单独证明轮胎欠转向或侧滑。

配置 `rear_offset=0` 将模型参考点放在 base_link/后轴原点；车体范围配置为前伸 0.52 m、后伸 0.10 m、半宽 0.16 m，`geometry_verified=true` 是归档配置标志。逐帧 audit 和话题 frame 标签没有独立测量实际原点位置或车体尺寸。横向误差描述该模型参考点，不是车体边缘净空；走廊约束关闭且几何仅有配置证据，不能据此保证真实赛道净空。

最大误差发生于 **84.127440 s**、参考进度 **22.968 m**，诊断速度仅 **2.418 m/s**，距切换 4.5 目标约 0.2 s，不能由此单独认定提速导致误差。RUNNING 的 **3,570 个**定位健康样本全部 ready，epoch 固定。NDT inlier 残差 P95 **7.792 cm** 是配准残差，不是定位位置误差。map→odom 平移参数最大单步变化 **18.040 cm**；平移与旋转共同作用到当时车位后的最大修正为 **5.121 cm**，两者不能等同。缺少外部位置真值，尚不能排除固定定位/参考偏差。

另有未来 Path 节点的几何筛查显示较小轮廓误差，但 Path header 是发布时间，并非精确计划起始时刻，而且车辆持续重规划；该筛查不能证明时间对齐的未来预测准确性，也不能确定偏差根因。

## 转向响应、约束与执行时序

离线响应比较在实际 `/vesc/command.steering_angle` 变化时刻传播 τ q̇+q=u，再用实测轮速计算 v tan(q)/[0.36(1+Kv²)]。对照信号是原生 `/rear_axle/imu.angular_velocity.z`，不是 EKF yaw rate。排除 RUNNING 首秒，要求轮速>0.5 m/s、命令速度>0.3 m/s、命令年龄≤40 ms、轮速插值间隔≤40 ms、RUNNING 诊断年龄≤250 ms。本次 `hipnuc=false`，该对照不是 HI13 测量。

在 **35,500 个**合格原生 IMU 样本上，已部署参数的 yaw-rate RMSE 为 **0.09908 rad/s**；相同实测输入代入旧 τ=0.08 s、K=0 的离线反事实为 **0.35861 rad/s**，降低约 72.4%。这支持本记录下、以实测轮速为条件的 yaw 响应预测，不是闭环跟踪提升 72.4%，也不是新旧控制器实车对照。未叠加独立纯延迟，未拟合额外增益或偏置。原查看器中平移转角→gyro 得到的 80 ms 不是独立物理延迟测量；其将 EKF yaw rate 描述为独立 MPCC 预测状态的表述也不准确。

| Runtime 指标 | 样本数 | P95 | 最大值 |
|---|---:|---:|---:|
| 原生求解耗时 | 3,564 次请求 | 1.371 ms | 5.875 ms |
| 提交→结果交付 | 3,564 次请求 | 2.159 ms | 6.670 ms |
| 提交→成功计划 activation | 3,560 次 activation | 39.374 ms | 44.335 ms |
| 发布间隔，输出速度>0.3 m/s | 8,950 个间隔 | 20.986 ms | 29.689 ms |

Activation 时长包含配置的 20 ms handover 与采样调度。以上时间边界重叠，不能相加；也不是执行器、定位到命令或整车物理响应延迟。

**3,564 次请求**中 **3,563 次**被接受，末次因停止过程中的权限/generation 变化取消；**3,560 次**activation 成功，**3 次**因 tuning revision 变化取消。最终 `failed=0`、`deadline_misses=0` 对应本次观察的 **0/3,564（0%）** 计数比率，不是未来失败概率上界。`handover_rejected=0`、`log_dropped=0`。启用前 FAULT 来自定位 epoch 变化，随后显式重新启用；RUNNING 持续至操作员停止。

转向速率限制触发的诊断样本为零；由于没有实际舵角反馈，仍不能排除机械限速。轮速×gyro 代理 |v r| 的 P95 为 **4.336 m/s²**、最大 **6.254 m/s²**，35,500 个合格样本中 **23.35%** 超过 3 m/s²。当前 ay=3 用于曲率速度规划，不是启用的横向加速度硬约束。IMU ay 是 specific force，不能直接当作轮胎力，代理超阈值也不证明违反了启用的硬约束。

下一项有用的比较是固定 4.5 目标和权重，在重复误差位置对齐估计状态、参考几何、计划未来恢复与随后实际运动。需要先解决计划时间对齐和定位不确定性，才能将偏差归因于转向、速度预测或轮胎行为。本次文档整理没有修改控制器代码或运行参数。
