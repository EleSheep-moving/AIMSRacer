# VESC 100 Hz 更新与验证

按用户指定，以 `EleSheep-moving/vesc` 的远端 `main` 提交 `6fb4f6734f8eb310479c00292ebe0950b810f764` 为 VESC 源码基准，增加 100 Hz 收发支持，并保留 AIMSRacer 的车辆扩展。AIMSRacer 原来内置的 VESC 目录改为 `src/vesc` 子模块，固定到已推送的 `9e054cced00d1d881524643838eb4f76148657d4`。

## 配置与实际行为

- VESC `telemetry_rate_hz: 100.0`：每 10 ms 查询一次 core 和一次 IMU。core 包含 ERPM、电机电流、输入电流、电压和故障码；轮速里程计随 core 到达更新。
- VESC `baud_rate: 921600`，关闭硬件流控。车辆仍使用 `/dev/ttyVESC → /dev/ttyACM0` USB CDC；UART baud 配置不等于 USB 带宽。
- 车辆 launch 显式设定选择器 `publish_rate_hz: 100.0`。转换器和 VESC 驱动收到指令后立即转发；电机和舵机各约 100 帧/s。独立选择器组件默认值仍为 200 Hz。
- 接收线程移除固定 5 ms 等待；发送期间保留数据存储，串行写完每一帧并处理部分写入，避免原异步 API 引用临时 packet 数据。接收线程共享的状态使用 atomic。
- MPCC `/drive` 新指令生产仍为 50 Hz；100 Hz 选择器发布的是最新选中的指令，并未将求解或新指令生成改为 100 Hz。

当前 VESC 子模块保留 AIMSRacer 原有的两层 watchdog（默认 0.10 s 指令超时）、转换器与驱动双重舵机限位、40 A 启动电流参数和 wheel odom 纵向速度方差扩展（默认 0.04）。车辆参数与替换前一致，只增加 `baud_rate` 和 `telemetry_rate_hz`。转换器 watchdog 每 10 ms 检查，驱动 watchdog 跟随遥测 tick。详见[车辆扩展验证](2026-10-13-vesc-vehicle-extensions.md)。指令队列现为深度 1，并按默认 0.10 s 有效期过滤；详见[发送与指令积压处理](2026-10-13-vesc-command-freshness.md)。

## 验证

原版本和新版本均在独立 ROS domain 下，以 PTY 模拟 VESC 跑选择器 → 转换器 → 驱动 → 轮速里程计完整链路。模拟器逐帧检查 CRC 和边界，反馈带已知 ERPM/电流的遥测，另有驱动回归测试验证分段响应与 50/100 Hz 参数。采样窗口 5 s：

| Topic / 串口帧 | 修改前 | 新版本 |
|---|---:|---:|
| `/sensors/core` | 50.0 Hz | 100.0 Hz |
| `/sensors/imu`、`/sensors/imu/raw` | 50.0 Hz | 100.0 Hz |
| `/rear_axle/wheel_odom` | 50.0 Hz | 100.0 Hz |
| `/ackermann_cmd` | 200.0 Hz | 100.0 Hz |
| `/commands/motor/speed`、`/commands/servo/position` | 200.0 Hz | 100.0 Hz |
| `/sensors/servo_position_command` | 200.0 Hz | 100.0 Hz |
| 串口 core / IMU 查询帧 | 各 50.0 Hz | 各 100.0 Hz |
| 串口 RPM / servo 指令帧 | 各 200.0 Hz | 各 100.0 Hz |

完整链路无串口帧错误。`driver_link` 与 `vehicle_extensions` CTest 共四个 pytest 场景通过，覆盖 50/100 Hz、两层 watchdog、恢复输入、舵机限位、启动电流和默认/覆盖方差。

实机用实际 ROS 驱动连接 AESC_60_Pro、固件 6.05，在独立 domain 内只查询遥测，不创建任何电机或舵机命令发布器。恢复车辆扩展后的实机复测，预热后采样 10 s，core 实测 **99.9 Hz**，IMU 和标准 IMU 实测 **100.0 Hz**；电压 19.8 V、ERPM 0、故障码 0，日志无 CRC/帧同步错误。下发指令的频率及内容验证采用 PTY，未进行实车运动测试。

原始记录保存在 NX 的 `/home/aims/aimsracer-data/sessions/2026-10-12/vesc-100hz/`，包括 `pipeline_results.json`、`hardware_results.json` 和运行日志。恢复车辆扩展后的记录位于 `/home/aims/aimsracer-data/sessions/2026-10-13/vesc-vehicle-extensions/`。

## 更新与复测

```bash
git pull --ff-only
git submodule update --init src/vesc
source /opt/ros/humble/setup.bash
colcon build --packages-select vesc_driver vesc_ackermann aims_racer_system
source install/setup.bash
python3 -m pytest -q src/vesc/vesc_driver/test/test_driver_link.py src/vesc/vesc_ackermann/test/test_vehicle_extensions.py
```

常规启动沿用现有 `vehicle.launch.py` 入口，无需增加频率覆盖参数。
