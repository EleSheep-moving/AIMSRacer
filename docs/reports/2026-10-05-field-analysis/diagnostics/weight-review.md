# 权重核查与后续对照思路（2026-10-06）

本轮只核查与提出调参思路，没有修改生产代码、实车 YAML、约束或 submodule，没有启动自动驾驶。

## 代码中真正使用的代价

参考集成仓库 aims_mpcc/solver.py 的 _build，而不是 vendor/normalized_cost.py 中独立旧示例的 weights。归一化分母参与平方，YAML 数字不能直接相互比较。

| 项目 | 现有权重 | 当前尺度 | 典型单步代价 |
|---|---:|---:|---:|
| 横向误差 | 16 | 0.05 m | 20 cm → 256 |
| 航向误差 | 4 | 0.05 rad | 15° → 109.0 |
| 速度误差 | 133.333 | 0.60 m/s | 0.2 m/s → 14.81 |
| 转向偏离曲率前馈 | 0.667 | 0.314159 rad | 0.1 rad → 0.06755 |
| 转向变化率 | 0.3 | 2 rad/s | 1 rad/s → 0.075 |
| 转向变化率的变化 | 0.3 | 0.2 rad/s 每 100 ms | 对应 1 rad/s² → 0.075 |

还有 lag=26.667、虚拟进度速度误差=1.333、acceleration=0.333 等固定项，以及 terminal_weight=3 对终端横向、lag、航向、速度项的整体放大。

这些是人为选定典型误差下的代价示例，不是实际最优解的代价分解。状态与输入之间受预测动态耦合，也有硬约束，不能仅根据单项数值大小判定某个权重错误。实车日志未保存完整的最优 states/controls 与逐项代价，无法精确回算真实求解中每项占比。

特别注意 steering_weight 惩罚的是 delta_command−delta_feedforward，而非单纯 delta_command；提高它会让控制更接近轨迹曲率要求的转向，仍允许过弯。

## 原仿真结果复核与记录纠正

原始 closed_loop.py 和 JSON 清楚记录的是提高转向相关惩罚。早先 README 曾误写为“降低”，已改正。原始实验没有改动。

| 12 秒理想模型实验 | 去掉最初 2 秒后横向误差 P95 | 未成功求解数 |
|---|---:|---:|
| 原配置 | 11.55 cm | 2 |
| heading 4 → 16 | 14.72 cm | 0 |
| steering 0.667 → 6.667 | 3.98 cm | 0 |
| rate 和 acceleration 惩罚一起 0.3 → 3.0 | 4.11 cm | 0 |

仅为短时、固定虚拟延迟、理想执行器模型、相同起点的离线敏感性实验，不是全圈或实车效果。转向变化率两项一起修改的实验不能区分两项各自的贡献。仿真时间统计不等于当前全部实车进程共运行时的性能保证。

现有证据支持优先检查转向纠偏与平滑惩罚，但不支持认定权重是唯一根因。此前已发现速度估计响应滞后、低速反馈差异和小的模型偏置，它们可能与激进反馈共同作用。

## 专业方法的参考

Autoware 建议先检查运动学、动态响应和实际输入，再固定横向误差权重，改变转向输入惩罚，比较摆动与精度之间的取舍；还可单独考虑转向变化率和终端项。其具体参数值不能直接用于本车，因为模型、归一化和求解结构不同。

https://autowarefoundation.github.io/autoware_universe/main/control/autoware_mpc_lateral_controller/#how-to-tune-mpc-parameters

MathWorks 建议先确定并固定归一化尺度，再调整相对权重；增加输入变化率惩罚有助于减少激进动作，但可能牺牲跟踪响应。它还明确要求检验模型误差下的表现。其线性 MPC 设置不是本车非线性 MPCC 的稳定性保证。

https://www.mathworks.com/help/mpc/ug/scale-factors.html
https://www.mathworks.com/help/mpc/ug/tuning-weights.html

## 后续对照顺序（尚未实施）

保持模型、horizon=10、5 Hz 调度、250 ms deadline、硬约束和起点条件一致。先在已成功完成一圈的 0.5 m/s 巡航工况做闭环对照；选出稳定候选后再逐步提高到 1.0 m/s。控制周期 0.2 s 与预测离散步长 0.1 s 分开记录。

1. 固定 contour=16、heading=4、speed 和 terminal 权重，单独对比 steering_weight 为 0.667 / 1.333 / 2.667 / 6.667。检验对曲率前馈的约束是否减轻过度纠偏。
2. 选定前一步候选后，单独对比 steering_rate_weight 为 0.3 / 0.6 / 1.2；再单独比较 steering_acceleration_weight。不得把两项同时变化的结果当作各项独立效果。
3. 对 heading 进行独立对照，观察过零后的反向纠偏和弯道表现；已有 heading ×4 仿真没有改善 P95，不能认为增大航向权重必然抑制摆动。
4. 横向控制稳定后，再检查 speed 权重与巡航目标。速度追踪与侧向/纵向加速度硬约束可能冲突，权重不能越过物理或规划限制。terminal=3 先固定，因为它同时放大终端速度和横向项。

评价应包含完整圈完成情况、横向误差 P50/P95/最大值、直线与弯道分开统计、转向纠偏幅度/频率、方向盘变化率、实际平均速度、求解成功率/迭代/耗时、硬约束贴边比例。相同条件重复比较，避免根据单个最顺的短段选权重。

首轮实际自动窗口中，约 30.8% 的 /drive 提议转角接近 ±0.45 rad 上限（绝对值 ≥0.44）；此前链路检查确认提议与选择命令匹配。说明约束饱和必须一起观察，不能只分析权重。该比例不包含制停后的样本，不代表物理轮胎角度饱和率。
