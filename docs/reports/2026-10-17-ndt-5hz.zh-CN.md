# NDT 5 Hz 配置与部署记录（2026-10-17）

将正常行驶 NDT 地图匹配从约 10 Hz 点云驱动调整为
`registration_frequency_hz: 5.0`，保留 `ndt_num_threads: 2`。
选择依据、频率与延迟区别见[定位监控文档](../localization_monitor.zh-CN.md)。
原回放显示约 35% 的 NDT CPU 节省，同时校正观测年龄 P95 从 223 ms 增至
308 ms。该选择侧重 CPU 与地图校正新鲜度折中，不是单帧延迟优化。

## 修改范围

- 在固定 NDT 依赖内增加源时间窗口采样器，200 ms 窗口取首个可用点云，
  在滤波和配准前丢弃其他帧；没有额外缓存、定时等待或补跑旧帧。
- 保留原始点云和 LIO、EKF/TF 的输入频率、独立质量检查和 50 Hz 位姿发布。
  `scan_period` 保留 0.1 s，继续描述点云扫描周期。
- 采样不刷新可信锚点；初始位姿/epoch/时钟重置清空采样状态。
  原有观测年龄、质量、恢复确认规则继续执行。
- 更新 `dependencies/ndt-trusted-anchor.patch` 及 manifest 哈希，包含实现、
  参数声明/读取、运行诊断、单元测试及依赖内部参数文档。
- 同步主 workspace 与 `calibration-full-step` 的源码配置和安装配置。
  中英文定位监控及架构文档同步说明修改依据。

## 实际运行入口

MPCC 的 `~/run_mpcc_imu_fit.sh` 使用
`/home/aims/AIMSRacer/install/setup.bash`。
标定的共享环境 `~/calibration_full_step_env.bash` 使用
`/home/aims/aimsracer-data/code/calibration-full-step/install/setup.bash`。
两个入口解析到的 NDT 可执行文件和 YAML 都需要核对，而不是只修改开发目录。
已有启动命令保持可用；本次未启动实车传感器、控制器或车辆运动。

## 生效与回退

参数在 lifecycle configure 时读取；重启定位或重新 configure 后生效。
运行中 `ros2 param set` 不会改变采样器。
将对应源码和安装 YAML 的 `registration_frequency_hz` 改为 `0.0` 并重启定位，
即可恢复原来的点云驱动匹配；不要把 `scan_period` 改成 0.2。

核对实际值可查看 configure 日志和 `/localization/anchor_status` 中
`lidar_localization/timing` 的 `registration_frequency_hz` 字段。
只查看 50 Hz 位姿或 TF 频率无法判断匹配频率。

## 验证记录

NX 编译和安装完成。34 项工程回归、265 项 NDT Python 检查、5 项采样与
可信锚点 C++ 检查通过；完整依赖补丁在固定版本的干净 checkout 上验证可应用，
应用后的完整 diff 与 manifest 哈希一致，NX 实际源码完整 diff 也一致。

安装后的程序直接接收同一 bag 60–120 s 的全部 **600 帧、10 Hz 点云**，
不做外部抽帧。通过 ROS 参数服务及逐次匹配诊断核对 **5.0 Hz、2 个匹配线程**：

| 指标 | 本次内部限频复测 |
|---|---:|
| 稳定段实际提交频率 | 5.0 Hz（284 次 / 56.8 s 测量区间） |
| NDT CPU（100% = 一个逻辑核） | 44.7% |
| 单帧处理平均 / P95 | 46.3 / 83.4 ms |
| 校正观测年龄 P95 / 最大 | 344 / 444 ms |
| 稳定段健康检查 ready | 100% |
| 首次 ready | 0.575 s |
| 相对原 10 Hz 的平面位置差异 P95 / 最大 | 2.28 / 4.92 cm |
| 相对原 10 Hz 的航向差异 P95 / 最大 | 0.73 / 1.98° |

将参数覆盖为 `0.0` 的独立短回放恢复到 **10.0 Hz** 提交，验证关闭采样的回退行为；
该覆盖仅用于测试，现场两份安装 YAML 仍为 5.0 Hz。

CPU 测量区间内进程线程集合稳定。位置和航向比较在同一当前 odom 上应用各自
最近一次源时间已提交校正，排除首 5 s 和末 0.5 s，延续前次比较方法；仍没有独立真值。
内部窗口选帧与此前外部每隔一帧抽样的相位不同，观测和监控采样相位也会影响数值。
因此本表单独报告，不把此前的 308 ms、1.80 cm、0.50° 当作新程序的延迟或精度保证。
回放仍统一使用 20 ms 时钟投递余量，未重新运行 FastLIO/EKF 或控制器闭环。

证据目录：`aimsracer-data/sessions/2026-10-17/ndt-5hz-deployment/`。
`verification.json`、`relative-comparison.json` 和 `installed-configs.json` 分别记录
验收、相对轨迹比较和两份实际安装配置；`backup/` 保存修改前的源文件、库、
可执行文件和配置。`installed-binaries.json` 冻结实际安装二进制哈希。

在 NX 上复现本次内部限频检查：

```bash
bash ~/aimsracer-data/sessions/2026-10-17/ndt-5hz-deployment/replay_native_5hz.sh 60
```

该脚本仅在独立 ROS domain 回放录制点云/TF/odom，启动定位和健康监控。
历史外部抽帧工具不能直接叠加本次内部采样；如要重新比较外部 10/5/2 Hz，
需要用新工具显式传入 `--registration-hz 0.0`。历史工具和证据保持原样，
说明见该证据目录的 `HISTORICAL_REPLAY_NOTE.md`。

本次软件验证不替代实车闭环、异常丢失恢复与完整采集到控制延迟验收。
