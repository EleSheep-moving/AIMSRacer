# PP and calibration scheduling replay

[简体中文](README.zh-CN.md)

`replay_runtime.py` runs the installed PP or calibration producer and selector beside raw FAST-LIO, EKF and NDT replay. It never starts a VESC driver. It forces a separate localhost-only ROS domain, supplies virtual RC permission and replays recorded motor telemetry with its source timestamps.

Build the feature overlay, source its `install/setup.bash`, then run:

```bash
python3 verification/calibration/replay_runtime.py \
  --bag /absolute/known-map/bag --map /absolute/map.pcd \
  --seed /absolute/map-base-link-seed.json --bundle /absolute/field-bundle \
  --output /absolute/new-evidence-directory --mode pp --seconds 60 --domain 223
```

Use `--mode calibration --domain 224` for the speed-hold producer. The output directory must be new. `--seed` uses the existing localization replay format (`position`, `orientation`, map/base_link semantics). The bundle must contain canonical `reference.json` and its `input_config.yaml`. The installed native TF audit is expected at `build/aims_racer_system/tf_authority_audit` in this checkout.

`summary.json` reports active output callback duration and publication intervals separately. P95 is the 95th percentile of measured samples, not a hard worst-case bound. PP sensor callbacks and inactive calibration states are excluded. Inspect controller CSV, status and localization evidence together; no active rows means the timing measurement is unqualified.

The helper creates a synthetic all-lap interval under its output directory solely for scheduling. **It is not a field-approved straight interval. Recorded car feedback was generated by the old commands, so this replay cannot validate the new requests, current response, physical calibration or field safety.** Do not use its synthetic reference for vehicle operation. Vehicle workflows are in [the operation guide](../../docs/operations/pp-calibration.md).

`--timing-rearms 40` explicitly calls the virtual enable service again after a fault and fresh localization, collecting timing across separate active segments. It defaults to zero. Every attempt is logged in `enable_responses`; this option belongs only to the isolated scheduling helper. Aggregate timing does not demonstrate continuous tracking or change production recovery behavior.
